# Agenda (tarjeta 46) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Disponibilidad semanal del PT, turnos con estados y anti-solapamiento en la base, notificaciones al alumno y calendario semanal en la web del PT.

**Architecture:** Tabla `trainer_availability` + índice único parcial en `appointments` + RPC de reemplazo atómico. Módulos backend `availability` y `appointments` con utilidades de fecha en hora de Argentina. Web: `AgendaPage` con grilla semanal, panel de turno y diálogos de disponibilidad y nuevo turno.

**Tech Stack:** Express ESM + supabase-js + Jest ESM (`npm test`); React 19 + TanStack Query 5 + Tailwind 4 + Vitest.

**Spec:** `docs/superpowers/specs/2026-10-31-agenda-design.md`

## Global Constraints

- CONTRIBUTING: archivos ≤ 200 líneas, carpetas ≤ 10 archivos (subdividir por tema), capa → módulo → archivo, tests espejo de `src` (un test dividido va en una carpeta con el nombre de la unidad), docs en la misma PR.
- Backend: `npm test` (nunca `npx jest`) y `npm run lint`. Web en `frontend/`: `npm test` y `npm run lint`.
- Commits en español (`feat(agenda): …`) **sin** trailers de IA.
- Sin dependencias nuevas.
- Zona: `America/Argentina/Buenos_Aires`. DB en UTC. Semana ISO lunes–domingo, weekday 1 = lunes.
- Turnos de 60 min en hora en punto. Alumno: hasta 28 días adelante. Rango de `/free`: 1–31 días. Rango de `GET /appointments`: 1–62 días. Notas de hasta 500. Hasta 50 franjas de disponibilidad.
- No ejecutar SQL contra Supabase: la migración la corre Pablo.
- Textos de UI y de errores en español rioplatense, literales de la spec.

## Review Focus

1. Dos `POST /appointments` simultáneos al mismo horario: uno da 201 y el otro 409 `SLOT_TAKEN` (23505 traducido), nunca 500.
2. Conversión Argentina ↔ UTC en los bordes: un turno a las 22:00 de Argentina es al día siguiente en UTC, y un lunes 00:00 de Argentina sigue siendo lunes en la grilla.
3. Transiciones de estado por rol: el alumno no puede confirmar, nadie puede reabrir un cancelado y un turno pasado no se toca.
4. `/availability/free` no ofrece horarios ocupados (`pending` o `confirmed`), pasados ni fuera de la disponibilidad, y sí los cancelados.
5. Push solo al alumno: las notificaciones al PT se guardan sin push.

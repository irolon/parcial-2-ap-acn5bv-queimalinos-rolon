# Plan — Pruebas de la web (tarjeta 53 · MIS 25)

Spec: `docs/superpowers/specs/2026-11-05-web-qa-design.md`. Rama `test/web-qa`. Reglas de CONTRIBUTING; commits sin firma de IA.

### Task 1: Línea base y tests inestables

- Línea base: 3 corridas con la config del CI y 1 por defecto (05/11, antes de tocar nada). Anotar qué falló en cada una.
- Por cada test que falló alguna vez: reproducirlo aislado y bajo carga (`--maxWorkers` alto), encontrar la causa y arreglarla en el test (o en el componente, si el bug es real). Sin subir timeouts globales.
- Criterio: 3 corridas seguidas en verde con la config del CI y 1 por defecto. Commit `test(web): tests estables …`.

### Task 2: Datos y entorno de prueba

- Backend local + web local (`.claude/launch.json`: `backend` y `web`), los dos desde este worktree.
- Los datos se arman con un script que usa la API (PT, 2 alumnos, ejercicios, rutina de los 7 días, una sesión con series y una medida), con emails de QA. El script no se commitea: es de una sola vez y la limpieza es `npm run test:integration:clean`.

### Task 3: Checklist y recorrido a mano

- Armar en `docs/proceso/pruebas-web.md` la checklist por rol y pantalla (Guía Web p. 5–15 + guards de rol) y los cuatro flujos críticos con su lado web y su simulación por la API.
- Recorrerla en el navegador integrado a 1366×768, y a 1280×720 las pantallas con tablas o grillas. Capturas en `docs/superpowers/specs/assets/53/`.
- Condiciones feas (Q5): backend caído a mitad de la sesión, `JWT_EXPIRES_IN=60s`, retardo artificial, dos pestañas, recarga.
- Cada bug con número, pasos, esperado/obtenido, severidad y estado.

### Task 4: Arreglos

- Críticos: siempre. Menores: si llevan menos de 30 min. TDD (test que reproduce el bug → arreglo). Un bug grande va en su propia rama `fix/…`.

### Task 5: Cierre

- `npm run lint`, `npm test` y `npm run build` en verde; link desde `plan-de-pruebas.md`; review de dos ejes; PR `test(web): pruebas de la web, bugs y tests estables (tarjeta 53)`; comentario en MIS 25.
